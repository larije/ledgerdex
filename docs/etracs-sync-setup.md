# eTRACS sync setup

LedgerDex reads the selected account's current record from eTRACS when an operator presses **Sync eTRACS**. eTRACS is queried only; LedgerDex stores the returned account details, latest totals and status, receipt allocations for that TD, and a separate year-end bill projection in its own database.

## Create a read-only eTRACS database identity

Ask the eTRACS database administrator to create a dedicated identity for the LedgerDex server. It needs `SELECT` on only these five tables:

- `rptledger`
- `rptledgerfaas`
- `rptledger_item`
- `rptpayment`
- `rptpayment_item`

Use your approved database name, LedgerDex server host, and a unique password in place of the placeholders below. Do not run this from LedgerDex. Confirm that the new account has no other grants or roles that allow writes.

```sql
CREATE USER 'ledgerdex_reader'@'<ledgerdex_server_host>' IDENTIFIED BY '<unique_secret>';
GRANT SELECT ON `<etracs_database>`.`rptledger` TO 'ledgerdex_reader'@'<ledgerdex_server_host>';
GRANT SELECT ON `<etracs_database>`.`rptledgerfaas` TO 'ledgerdex_reader'@'<ledgerdex_server_host>';
GRANT SELECT ON `<etracs_database>`.`rptledger_item` TO 'ledgerdex_reader'@'<ledgerdex_server_host>';
GRANT SELECT ON `<etracs_database>`.`rptpayment` TO 'ledgerdex_reader'@'<ledgerdex_server_host>';
GRANT SELECT ON `<etracs_database>`.`rptpayment_item` TO 'ledgerdex_reader'@'<ledgerdex_server_host>';
```

The application issues parameterized `SELECT` queries against these five tables only. It does not call procedures or issue writes or DDL to eTRACS. Keep the eTRACS identity SELECT-only as the final protection if application code changes later.

## Year-end projection

Each successful sync also calculates an estimated eTRACS bill as if it were computed on December 31 of the current calendar year in the `Asia/Manila` time zone. It includes Q4, uses the current eTRACS tax items and non-voided principal allocations through the sync time, excludes advance tax years after the projection year, and assumes no payments after the sync. The estimate follows the deployed billing rules reviewed for this integration: prior-year monthly penalties, the 72% cap for 1992-and-later prior-year items, Q1–Q3 current-year penalties, and the 10% Q4 discount. Tax-difference lines do not receive those penalties or discounts. Special bill options that are not represented in the ledger rows, such as an eTRACS-only back-tax flag, cannot be inferred. This amount is labeled as a projection in LedgerDex; it is not a bill generated by eTRACS.

The projection formula is implemented in LedgerDex. If eTRACS's deployed billing rules change, review and update the LedgerDex projection before relying on it. The regular eTRACS snapshot remains separate from the projection, and both remain separate from LedgerDex local figures and settlement history. The account detail's primary status follows the latest eTRACS snapshot after sync; the local status and local payment history remain visible separately.

## Configure LedgerDex

Set `ETRACS_DATABASE_URL` in the server's private environment file or secret manager. Use a MySQL URL for the dedicated reader account. The example value in `.env.example` is a placeholder; never commit the real URL or expose it through a `NEXT_PUBLIC_` variable. Set `ETRACS_READ_ONLY_CONFIRMED=true` only after the database administrator has confirmed that the configured identity has SELECT-only grants on the listed tables and no write-capable roles.

```dotenv
ETRACS_DATABASE_URL="mysql://ledgerdex_reader:<url_encoded_password>@<etracs_host>:3306/<etracs_database>"
ETRACS_READ_ONLY_CONFIRMED="true"
```

The route bounds the Prisma connection pool and allows up to 120 seconds for a large eTRACS account read, with a 150-second route duration for final persistence. Projection reads are capped at 50,000 rows per source set to protect memory without rejecting ordinary long histories. If a record exceeds the time limit, LedgerDex reports a timeout and keeps the previous snapshot. Restart the LedgerDex server after changing this setting.

## Apply the LedgerDex schema change before deploying the feature

The feature uses `etracs_sync_snapshots`, `property_etracs_sync_snapshots`, and the `EtracsStatus` enum in LedgerDex only. Both snapshot tables also store a JSON `paymentHistory` and a `paymentHistoryTruncated` flag, in addition to nullable `projectedAmountDue` and `projectionYear` fields. Receipt history is scoped through the selected ledger's `rptledgerfaas` rows, so older receipts remain visible when a ledger has no current `rptledger_item` rows. Receipt allocations are grouped by FAAS; voided receipts appear in history but are excluded from official paid totals. Principal totals and the projection continue to use the selected ledger's assessment rows, matched by `rptledgerfaasid`, `year`, and `revtype`. Existing LedgerDex status, figures, and local payment rows stay separate. Apply the schema changes to LedgerDex **before deploying this application version**: account and property detail loads query their snapshot tables even when eTRACS sync is not configured, so deploying first will break those pages until the tables exist. Back up LedgerDex, review all pending changes in the current `prisma/schema.prisma`, and apply the additive schema changes using the deployment's approved Prisma schema process (for this repository, `npm run db:push` targets the LedgerDex `DATABASE_URL`). Do not point `DATABASE_URL` at eTRACS.

## Operator messages

- **Not configured:** the server has no valid `ETRACS_DATABASE_URL` or `ETRACS_READ_ONLY_CONFIRMED` is not `true`; ask an administrator to configure and verify the read-only account.
- **No match:** no exact TD number was found; LedgerDex retains its previous values.
- **Multiple matches:** eTRACS returned more than one exact TD; LedgerDex retains its previous values and an administrator should resolve the duplicate.
- **Unavailable:** eTRACS could not be reached or the query failed; LedgerDex retains its previous values. Check connectivity and the reader grants.
- **Invalid source data:** required financial values could not be safely interpreted; LedgerDex retains its previous values.

The successful sync updates the existing LedgerDex delinquency account or property details and replaces that record's latest eTRACS snapshot. LedgerDex's imported amounts, tax/payment fields, and local settlement or payment history remain available as local reference data; they are not merged into eTRACS totals.
